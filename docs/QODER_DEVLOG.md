# Qoder 开发记录（溯文 SeekLit）

> 比赛要求说明「Qoder 使用」。本项目从空目录到可发布站点，全部编码、调试、验证、
> 截图、文档与站点构建都在 Qoder 会话里完成。下面是按时间线记的实录，
> 包含走过的弯路——弯路也是 Qoder 用法的一部分。

## 开发方式

- **远程执行**：本机性能弱，Qoder 通过 SSH 在服务器 `219.216.64.186` 的
  `/root/ryh/newproject` 内完成全部服务器侧操作（隔离 seekdb 实例、导入、检索、起服务），
  全程未触碰该目录之外的任何进程与文件。
- **本地编辑 + 同步**：源码在本地用 Qoder 的文件工具编辑，`pscp` 同步到服务器；
  服务器侧只跑命令、回传日志与快照。
- **证据驱动**：每个技术结论都先写探针脚本跑真实查询（`scripts/probe_*.py`、
  `scripts/verify_paths.py`），把 seekdb 的报错原文与生成 SQL 落盘成证据，再写进文档与前端展示。
- **浏览器验证**：先用 Qoder 内置浏览器点真实按钮验证交互（预设问题点击 → 8 条结果 →
  SQL 抽屉），再用本机 headless Edge 按 1440×900 截桌面宽度截图（内置浏览器视口固定过窄）。
- **站点交付**：使用 Qoder Sites 技能（sites-building / sites-hosting）构建并发布项目站点，
  站点内嵌离线检索快照，评审无需连服务器即可交互。

## Qoder 在本项目里做对的三件事

1. **把报错当线索而不是障碍**：1191 与 1235 两个报错直接塑造了表结构（三全文索引、无用户主键），
   并变成站点上可展示的「seekdb 行为解剖」。
2. **所有数字可复算**：效果表、耗时、排名差异都附采集脚本与原始日志，评审可一键重跑。
3. **演示不依赖服务器**：快照里带每段的真实 vsim / bm25，站点在浏览器里重做加权融合与 RRF，
   评审拖滑块看到的每个分数都能对应回快照中的原始值。

## 已知限制（如实记录）

- 默认向量化是离线 LSA，语义上限低于 bge-m3 一类神经模型；后端可一行环境变量切换，切换后需重灌 `emb`。
- 未做人工标注，因此不报 precision/recall，只报召回量、两路重合度、排名变动与耗时（见 SEEKDB_EVIDENCE.md 第 5 节）。
- 原生 RRF 路径约 116–134 ms，比单路慢一个数量级，是窗口函数 + 双路召回的固有代价；对 8 段返回的交互场景可接受。
